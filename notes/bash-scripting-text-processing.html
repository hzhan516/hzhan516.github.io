Bash Scripting and Text Processing: Building a Log Audit Script

Redirection, pipes, variables, conditionals, loops, regular expressions, grep, sed, and awk, learned by building one SSH log audit script step by step.

Goal and sample data

This note builds log-audit.sh from scratch. The script reads an RHEL-style SSH security log (/var/log/secure), counts failed logins, groups them by source IP, lists successful logins, and uses its exit code to tell the caller whether an alert is needed. Each section introduces one topic and grows the script a little. The complete version is at the end.

Start by creating a sample log with a heredoc (explained below). Every output shown in this note comes from running the commands against this data.

mkdir -p ~/log-audit && cd ~/log-audit
cat > sample-secure.log <<'EOF'
Nov  5 08:01:12 servera sshd[1201]: Failed password for root from 192.168.1.50 port 50122 ssh2
Nov  5 08:01:15 servera sshd[1201]: Failed password for root from 192.168.1.50 port 50122 ssh2
Nov  5 08:02:03 servera sshd[1210]: Accepted password for student from 192.168.1.10 port 50200 ssh2
Nov  5 08:03:44 servera sshd[1222]: Failed password for invalid user admin from 203.0.113.7 port 41000 ssh2
Nov  5 08:03:47 servera sshd[1222]: Failed password for invalid user admin from 203.0.113.7 port 41000 ssh2
Nov  5 08:03:50 servera sshd[1222]: Failed password for invalid user test from 203.0.113.7 port 41002 ssh2
Nov  5 08:05:10 servera sudo[1300]:  student : TTY=pts/0 ; PWD=/home/student ; USER=root ; COMMAND=/usr/bin/dnf update
Nov  5 08:06:21 servera sshd[1310]: Failed password for student from 192.168.1.10 port 50300 ssh2
Nov  5 08:06:30 servera sshd[1311]: Accepted publickey for operator from 10.0.0.5 port 52000 ssh2
Nov  5 08:07:02 servera sshd[1320]: Failed password for root from 192.168.1.50 port 50400 ssh2

The finished script prints this:

$ ./log-audit.sh sample-secure.log

-- Failed logins by source IP --

192.168.1.50        3  root                 ALERT

$ echo $?

On a real system

Reading /var/log/secure on RHEL requires root, for example sudo ./log-audit.sh /var/log/secure. The sample file is enough for practice.

The first script: shebang, permissions, and debugging

A shell script is a text file of commands that run in order. Moving repeated command-line work into a script cuts typing mistakes and makes the work reusable and reviewable.

The shebang

The first line starts with #!, called the shebang (or hash-bang). When the kernel executes the file, it reads this line and runs the script with the interpreter named there:

#!/bin/bash
echo "log-audit: starting"
  • The interpreter path must exist. Otherwise you get bad interpreter: No such file or directory.
  • Without a shebang, the result depends on the caller. Bash usually runs the file in a new Bash process, but other programs may refuse to execute it. Always include the shebang.
  • For portability across systems, #!/usr/bin/env bash finds bash through PATH.

Permissions and ways to run a script

chmod +x log-audit.sh      # add execute permission
./log-audit.sh             # run from the current directory; needs +x; uses the shebang
bash log-audit.sh          # run bash explicitly; no +x needed; the shebang is ignored
~/log-audit/log-audit.sh   # absolute path

The shell looks up commands only in the directories listed in PATH, and the current directory is not one of them, so you need ./. If you put the script in ~/bin or /usr/local/bin (both in the default RHEL PATH), you can run it by name.

Both ./script and bash script run the script in a child process, so variables it sets do not affect your shell. source script (or . script) runs it in the current shell, which is how configuration files are loaded.

Debugging and safety options

Command Effect
bash -n script Check syntax without running
bash -x script or set -x inside Print each expanded command to stderr before running it, prefixed with +
set +x Turn tracing off
set -e Exit as soon as a command returns a non-zero status
set -u Treat references to unset variables as errors
set -o pipefail A pipeline fails if any command in it fails 
$ bash -xc 'n=2; echo $((n*2))'
+ n=2
+ echo 4
4

log-audit.sh puts set -euo pipefail right after the shebang so errors surface early. The cost is that commands that can legitimately "fail", such as grep finding no match (status 1), need an explicit || true.

I/O channels and redirection

Every process starts with at least three file descriptors (fds):

fd Name Default Purpose
0 stdin keyboard read only
1 stdout terminal write only, normal output
2 stderr terminal write only, errors and diagnostics
3+ other files none files the program opens

Redirection changes where these channels point, so a process reads from or writes to a file instead of the terminal.

Syntax Meaning
> file stdout to file, overwrite
>> file stdout to file, append
2> file stderr to file, overwrite
2>/dev/null discard stderr
> file 2>&1 or &> file stdout and stderr to file, overwrite
>> file 2>&1 or &>> file stdout and stderr to file, append
< file read stdin from file
>&2 send this command's stdout to stderr

Order matters

Bash processes redirections from left to right. 2>&1 means "point fd 2 wherever fd 1 points right now":

$ ls /etc/hostname /nope > out.txt 2>&1; cat out.txt
ls: cannot access '/nope': No such file or directory
/etc/hostname

$ ls /etc/hostname /nope 2>&1 > out.txt; echo '--file:'; cat out.txt
ls: cannot access '/nope': No such file or directory
--file:
/etc/hostname

The first command points stdout at the file, then sends stderr to the same place, so both end up in the file. The second points stderr at the terminal (where stdout was at that moment) and only then moves stdout to the file, so the error still reaches the terminal.

Error messages in scripts

Unless a command reports an error, everything a script prints with echo goes to stdout. Usage text and error messages belong on stderr. That way they don't end up in a report the user redirected to a file, and a downstream command in a pipe won't treat them as data:

usage() {
    echo "Usage: $(basename "$0") LOGFILE..." >&2
    exit 1
}

Heredocs

Text between <<'EOF' and a line containing only EOF becomes the command's stdin, which is handy for generating files or multi-line input. With a quoted delimiter, $variables in the body are not expanded. Without quotes they are:

$ cat <<EOF
user: $USER-ish
EOF
user: doyle-ish

The related form <<< is a here string. It feeds one string to stdin, and the script uses it to hand variable contents to awk or wc, as in wc -l <<< "$failed".

Pipes, tee, and xargs

The pipe | connects the stdout of the command on its left to the stdin of the command on its right. In a chain, data flows through each command in turn, and each step does one job:

$ awk '/Failed/{print $11}' sample-secure.log | sort | uniq -c | sort -rn
      3 192.168.1.50
      2 admin
      1 test
      1 192.168.1.10

(admin and test are a field-shift bug that the sed section fixes.)

  • Redirection moves data into or out of files. A pipe sends data to another process.
  • A pipe carries only stdout. To include stderr, write 2>&1 | or |&.
  • On a single command, redirection takes effect before the pipe. ls /etc/hostname > out.txt | wc -l prints 0, because stdout already goes to the file and nothing enters the pipe.

tee: save and pass along

tee works like a T-junction in a pipe. It writes stdin to a file and to stdout at the same time, so you can save a report and still see it:

$ ./log-audit.sh sample-secure.log 2>&1 | tee report.txt | tail -1
2 source(s) reached the threshold

tee -a appends. A common use is echo "line" | sudo tee -a /etc/some.conf. Writing sudo echo ... >> file fails because your own unprivileged shell performs the redirection.

xargs: turn stdin into arguments

Some commands take arguments and ignore stdin (rm, ls, ssh-copy-id). xargs converts stdin into arguments:

find /etc -maxdepth 1 -name 'host*' 2>/dev/null | xargs ls -ld
printf 'a\nb\n' | xargs -I {} echo 'host={}'     # -I sets a placeholder; runs once per line
awk '{print $1}' hosts.list | xargs -I {} ssh-copy-id root@{}

find ... | ls -l is a classic mistake. ls never reads stdin, so it just lists the current directory. When file names may contain spaces, use find -print0 | xargs -0.

Variables, quoting, and the environment

Assignment and expansion

Variable names may contain letters, digits, and underscores, and cannot start with a digit. No spaces are allowed around =:

threshold=3                # correct
threshold = 3              # wrong: runs a command named threshold
echo "$threshold"          # expand
echo "${threshold}rd"      # braces delimit the name
today=$(date +%F)          # command substitution
threshold=${THRESHOLD:-3}  # use 3 when THRESHOLD is unset or empty

set lists every variable and function in the current shell, and unset name removes a variable.

Quoting

Some characters mean something to the shell ($, space, *, ;, |, and others). Three tools remove that meaning:

Tool Effect
Backslash \ Escapes the next character only
Single quotes '...' Everything is literal; nothing expands
Double quotes "..." Keep spaces, but still expand $var, $(cmd), and `cmd` 
$ name=world; echo 'single: $name' "double: $name" escaped: \$name
single: $name double: world escaped: $name

Rules of thumb: always double-quote expansions ("$file"), or a value containing spaces splits into several arguments. Put regular expressions and awk programs in single quotes so the shell doesn't touch their $ and *.

Shell variables and environment variables

A plain variable belongs to the current shell only. export turns it into an environment variable, which child processes started afterwards (including scripts) can see:

$ FOO=shell; bash -c 'echo child sees: [$FOO]'
child sees: []
$ export FOO; bash -c 'echo child sees: [$FOO]'
child sees: [shell]
$ export -n FOO      # stop exporting; FOO stays as a shell variable
$ unset FOO          # remove it entirely
  • env lists environment variables. set lists all variables.
  • VAR=value command sets an environment variable for that one command. log-audit.sh takes its settings this way: THRESHOLD=5 ./log-audit.sh sample-secure.log.
  • PATH is the most important environment variable, since it decides where the shell looks for commands. Variables such as HISTFILE, HISTFILESIZE, and HISTTIMEFORMAT="%F %T " tune history (the format codes match date).

Startup files

Which files Bash reads at startup depends on how it starts:

File Scope Read by
/etc/profile, /etc/profile.d/*.sh all users login shells
~/.bash_profile one user login shells (on RHEL it also loads ~/.bashrc)
~/.bashrc one user interactive non-login shells, such as a new terminal window
/etc/bashrc all users loaded from ~/.bashrc

A script running non-interactively reads none of these. It only inherits the variables its parent exported. So a script must not rely on variables or functions defined in your ~/.bashrc. Set what it needs inside the script, or pass it in through the environment. After editing a startup file, run source ~/.bashrc to apply it to the current shell.

Arguments, exit codes, and exec

Positional parameters

Variable Meaning
$0 Script name (the path used to call it)
$1 … $9, ${10} Arguments 1 through N
$# Number of arguments
"$@" All arguments, each kept separate
"$*" All arguments joined into one string with spaces
$? Exit code of the last command
$$ PID of the current shell

The difference between "$@" and "$*" shows when arguments contain spaces:

#!/bin/bash
# args.sh
echo "\$# = $#"
for a in "$@"; do echo "  \"\$@\" -> [$a]"; done
for a in "$*"; do echo "  \"\$*\" -> [$a]"; done
for a in $*;   do echo "  \$*   -> [$a]"; done

$ ./args.sh 'web 01' db
$# = 2
  "$@" -> [web 01]
  "$@" -> [db]
  "$*" -> [web 01 db]
  $*   -> [web]
  $*   -> [01]
  $*   -> [db]

To loop over arguments, almost always use "$@". Unquoted $* (and unquoted $@) split again on spaces. log-audit.sh passes all log files to grep unchanged with "$@".

Exit codes

Every command ends with an exit code from 0 to 255. Zero means success, non-zero means failure, and different non-zero values can identify different errors. The parent reads the code from $?. A script calls exit N to stop early with code N. Without exit, it returns the code of its last command.

$ bash -c 'false; echo rc=$?; exit 7'; echo outer=$?
rc=1
outer=7

log-audit.sh uses 0 for a clean run, 1 for usage or input errors, and 2 when a source reaches the alert threshold. Cron or a monitoring system can then act on the result without parsing text.

Watch grep's exit codes: 0 for a match, 1 for no match, 2 for an error. Under set -e, "no match" would end the script, hence grep ... || true.

exec

exec has two uses:

  1. exec command replaces the current shell process with the command. The PID stays the same, and nothing after it in the script runs. Wrapper scripts use it as their last step, for example exec java -jar app.jar "$@".
  2. exec with only redirections changes the current shell's own file descriptors for every command that follows.
#!/bin/bash
echo "before exec"
exec echo "exec replaced the shell"
echo "never printed"

log-audit.sh uses the second form for OUTPUT=file. From that point on, all stdout goes to the file while error messages still reach the terminal.

if [ -n "${OUTPUT:-}" ]; then
    exec > "$OUTPUT"
fi

Tests and conditionals

test expression and [ expression ] are the same command. The result comes back as an exit code: 0 when true, 1 when false. [ is a command name, so it needs spaces on both sides.

$ x=5; [ $x -gt 3 ]; echo $?; [ $x -eq 3 ]; echo $?
0
1

Common tests

Numbers Strings Files
-eq equal = or == equal -e exists
-ne not equal != not equal -f regular file
-gt greater than -z empty -d directory
-ge greater or equal -n not empty -r / -w / -x readable / writable / executable
-lt less than -s size greater than zero
-le less or equal -L symbolic link

! negates a test, and && / || combine tests: [ -f "$f" ] && [ -r "$f" ].

[[ ]] and (( ))

  • [[ ... ]] is a Bash keyword. Unquoted variables inside it don't split, and it supports glob matching [[ $host == server* ]] and regex matching [[ $n =~ ^[0-9]+$ ]].
  • (( ... )) evaluates integer arithmetic and comparisons, and variables inside need no $: (( fails >= limit )).
  • $(( ... )) returns the result:
$ a=10; echo $(( a + 1 )) $(( a / 3 )) $(( a % 3 )) $(( a * 3 )) $(( a ** 2 ))
11 3 1 30 100

Bash arithmetic is integer only, so 10/3 gives 3. For decimals, use awk 'BEGIN{printf "%.2f\n", 10/3}' or bc.

if / elif / else

if (( fails >= limit )); then
    status=ALERT
elif (( fails > 0 )); then
    status=WARN
else
    status=OK
fi

Bash tests the conditions in order, runs the first branch whose condition holds, and skips the rest. If none holds, it runs else. The condition can be any command, not only [ ]: if grep -q root "$file"; then ....

For simple cases, && and || are shorter: [ $# -ge 1 ] || usage.

Input checks in the script

[ $# -ge 1 ] || usage
threshold=${THRESHOLD:-3}
[[ $threshold =~ ^[0-9]+$ ]] || { echo "error: THRESHOLD must be a number" >&2; exit 1; }

Loops

for

for file in "$@"; do              # loop over arguments
    if [ ! -r "$file" ]; then
        echo "error: cannot read $file" >&2
        exit 1
    fi
done

for i in $(seq 2 2 8); do ...     # 2 4 6 8: start, step, end
for i in {1..5}; do ...           # brace expansion
for ((i=1; i<=3; i++)); do ...    # C style

Reading a file line by line: use while read

for line in $(cat file) is a common mistake. It splits on whitespace, not on lines:

$ printf 'web 01\ndb\n' > hosts.txt
$ for h in $(cat hosts.txt); do echo "[$h]"; done
[web]
[01]
[db]
$ while read -r h; do echo "[$h]"; done < hosts.txt
[web 01]
[db]

read -r turns off backslash escapes. read can also split a line into several variables, and the last one receives the rest of the line. The successful-logins part of the script uses this:

awk '{ print $9, $11, $7 }' <<< "$accepted" | sort | uniq -c |
while read -r count user ip method; do
    printf '%-10s from %-15s via %-9s x%d\n' "$user" "$ip" "$method" "$count"
done

A while loop on the right side of a pipe runs in a subshell, so variables set inside it are gone after the loop. To keep them, use done < file or done < <(command).

until condition; do ...; done loops until the condition holds. break leaves a loop, and continue starts the next iteration.

Regular expressions and grep

A regular expression is a small language for describing text patterns. grep, sed, awk, vim, less, and languages like Python and Perl all use it. Linux tools use two flavors:

  • BRE (basic) is the default for grep and sed. ?, +, {}, (), and | only become special when written \?, \+, \{\}, \(\), \|.
  • ERE (extended) is used by grep -E, sed -E, and awk. Those symbols work directly, which reads more clearly.
$ printf 'catcat\ncat\n' | grep 'c\(at\)\{2\}'      # BRE
catcat
$ printf 'catcat\ncat\n' | grep -E '(cat){2}'       # ERE, same match
catcat

Metacharacters

Pattern Meaning Example
. any single character c.t matches cat, c5t
[abc] / [^abc] one character in / not in the set c[aou]t matches only cat, cot, cut
^ / $ start / end of line ^cat$ is a line containing only cat
* previous item zero or more times c.*t starts with c, ends with t (not c*t)
+ previous item one or more times (ERE) [0-9]+
? previous item zero or one time (ERE) colou?r
{n} {n,} {,m} {n,m} repetition counts (ERE) c.{2}t matches coat
(a\|b) grouping and alternation (ERE) (admin\|test)
\b / \B word boundary / not a boundary \broot\b
\< / \> start / end of a word \<cat
\w / \W word character [_[:alnum:]] / non-word
\s / \S whitespace / non-whitespace

POSIX character classes go inside brackets, as in [[:digit:]]+:

Class Meaning
[:alnum:] letters and digits
[:alpha:] letters
[:digit:] digits 0-9
[:xdigit:] hexadecimal digits
[:lower:] / [:upper:] lowercase / uppercase letters
[:blank:] space and tab
[:space:] all whitespace, including newline, carriage return, and vertical tab
[:punct:] punctuation
[:print:] / [:graph:] printable characters with / without space
[:cntrl:] control characters

See man 7 regex for the full reference.

Extracting data with grep

$ grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' sample-secure.log | sort -u

The script uses grep first, to pull the relevant lines into variables:

failed=$(grep -hE 'sshd\[[0-9]+\]: Failed password' "$@" || true)
accepted=$(grep -hE 'sshd\[[0-9]+\]: Accepted ' "$@" || true)

-h drops the file name prefix that grep adds with several files, so every line has the same format. \[ matches a literal bracket.

sed in depth

sed (stream editor) reads input one line at a time, runs a set of commands on each line, and prints the result. It suits rule-based batch edits like substitution, deletion, insertion, and extraction, and it is the usual tool for editing configuration files from a script.

How sed runs

  1. Read a line, strip the newline, and place it in the pattern space.
  2. Run each command whose address matches.
  3. Print the pattern space (unless -n is set), clear it, and read the next line.

A second buffer, the hold space, keeps data between lines. It starts empty.

Basic form: sed [options] 'address command' file.

Option Effect
-n don't auto-print; output only what p prints
-E use ERE
-e script add a script fragment; can repeat
-f file read the sed script from a file
-i[suffix] edit the file in place; with a suffix, keep a backup such as -i.bak

Addresses

Address Selects
3 line 3
$ the last line
2,5 lines 2 through 5
/re/ lines matching the regex
/re1/,/re2/ from a line matching re1 to the next line matching re2
1~4 every 4th line starting at line 1 (GNU)
addr! lines that do not match the address 
$ sed -n '3p' sample-secure.log
Nov  5 08:02:03 servera sshd[1210]: Accepted password for student from 192.168.1.10 port 50200 ssh2
$ sed -n '/sudo/,/publickey/p' sample-secure.log
Nov  5 08:05:10 servera sudo[1300]:  student : TTY=pts/0 ; PWD=/home/student ; USER=root ; COMMAND=/usr/bin/dnf update
Nov  5 08:06:21 servera sshd[1310]: Failed password for student from 192.168.1.10 port 50300 ssh2
Nov  5 08:06:30 servera sshd[1311]: Accepted publickey for operator from 10.0.0.5 port 52000 ssh2
$ sed -n '/Accepted/=' sample-secure.log      # = prints the line number
3
9

The s command

s/regex/replacement/flags. Any character can be the delimiter. When the pattern contains paths, # or | is easier to read: s#/usr/bin/#BIN:#.

Flag Effect
g replace every match on the line (default is the first only)
N (a number) replace only the Nth match
I ignore case (GNU)
p print the line if a substitution happened; usually with -n
w file write the line to a file if a substitution happened

In the replacement, & is the whole match and \1…\9 are groups (\(\) in BRE, () in ERE):

$ sed 's/[0-9]\{1,3\}\.[0-9]\{1,3\}\.[0-9]\{1,3\}\.[0-9]\{1,3\}/<&>/' sample-secure.log | sed -n '1p'
Nov  5 08:01:12 servera sshd[1201]: Failed password for root from <192.168.1.50> port 50122 ssh2

$ sed -E 's/from ([0-9.]+) port ([0-9]+)/from \2:\1/' sample-secure.log | sed -n '1p'
Nov  5 08:01:12 servera sshd[1201]: Failed password for root from 50122:192.168.1.50 ssh2

$ sed -E 's/([0-9]+\.[0-9]+\.[0-9]+)\.[0-9]+/\1.xxx/g' sample-secure.log | sed -n '3p'
Nov  5 08:02:03 servera sshd[1210]: Accepted password for student from 192.168.1.xxx port 50200 ssh2

$ sed -n 's/Failed/FAILED/2p' <<< 'Failed Failed Failed'
Failed FAILED Failed

$ sed -n '/Failed/{s/.*from \([0-9.]*\).*/\1/;p}' sample-secure.log | sort | uniq -c
      1 192.168.1.10
      3 192.168.1.50
      3 203.0.113.7

The third example masks IP addresses before you share a log. The last one groups commands under a single address with {}, extracting the IP from Failed lines only.

The hold space

Command Effect
h / H copy / append the pattern space to the hold space
g / G copy / append the hold space to the pattern space
x swap the two buffers

Reverse the line order (like tac):

$ printf 'a\nb\nc\n' | sed -n '1!G;h;$p'
c
b
a

Line by line: line 1 (a) skips G, and h saves it. On line 2, G appends the hold space to give b\na, which h saves again. On the last line the pattern space holds c\nb\na, and $p prints it.

Join blank-line-separated paragraphs into single lines:

$ printf 'para1 a\npara1 b\n\npara2 a\npara2 b\n' | sed -n '/./{H;$!d};x;s/\n/ /g;s/^ //;/./p'
para1 a para1 b
para2 a para2 b

Non-empty lines accumulate in the hold space with H, and d ends the cycle unless it is the last line. On a blank line or the last line, x swaps the paragraph out, newlines become spaces, and the result is printed.

Editing configuration files in place

$ printf 'key=old\n' > c.conf
$ sed -i.bak 's/^key=.*/key=new/' c.conf; cat c.conf c.conf.bak
key=new
key=old

When you change system configuration, always pass a backup suffix, and preview the result without -i first.

In the script: normalize the data with sed

Printing the fields of line 4 shows the problem. invalid user adds two words and shifts every later field to the right:

$ sed -n '4p' sample-secure.log | awk '{for (i=6; i<=NF; i++) printf "$%d=%s ", i, $i; print ""}'
$6=Failed $7=password $8=for $9=invalid $10=user $11=admin $12=from $13=203.0.113.7 $14=port $15=41000 $16=ssh2

That is why admin and test showed up in the earlier uniq -c output. Normalize both formats with sed before awk sees them:

$ sed -E 's/ for invalid user / for /' sample-secure.log | sed -n '4,6p'
Nov  5 08:03:44 servera sshd[1222]: Failed password for admin from 203.0.113.7 port 41000 ssh2
Nov  5 08:03:47 servera sshd[1222]: Failed password for admin from 203.0.113.7 port 41000 ssh2
Nov  5 08:03:50 servera sshd[1222]: Failed password for test from 203.0.113.7 port 41002 ssh2

failed=$(grep -hE 'sshd\[[0-9]+\]: Failed password' "$@" \
    | sed -E 's/ for invalid user / for /' || true)

After this, the user name is always $9 and the IP is always $11.

awk in depth

awk treats its input as records (one line by default), and splits each record into fields (on runs of whitespace by default). An awk program is a list of pattern { action } rules. For each record, awk checks every pattern and runs the action when it matches. It suits column extraction, filtering, counting, and formatted reports.

Fields and built-in variables

Variable Meaning
$0 the whole record
$1…$N field N; $NF is the last, $(NF-1) the second to last
NF number of fields in the record
NR records read so far, across all files
FNR record number within the current file
FS / OFS input / output field separator; -F sets FS
RS / ORS input / output record separator
FILENAME current file name 
$ awk '{print $1, $2, $3}' sample-secure.log | head -2
Nov 5 08:01:12
Nov 5 08:01:15
$ awk -F: 'BEGIN{OFS=" -> "} NR<=2 {print $1, $6}' /etc/passwd
root -> /root
bin -> /bin
$ awk 'END{print NR}' sample-secure.log
10

In the first example, the two spaces in Nov 5 became one. The default FS treats any run of whitespace as one separator, and print joins fields with OFS (a single space). cut -d' ' treats every space as a separator, which makes it fragile on logs like this one.

Patterns

Pattern Example
regex /Accepted/
field match $5 ~ /^sudo/, $6 !~ /Failed/
comparison $3 >= 1000, $6 == "Failed"
combination /Failed/ && /root/, !/sshd/
range NR==2, NR==4
BEGIN / END run once before input / after all input 
$ awk '/Accepted/ {print $9, $11}' sample-secure.log
student 192.168.1.10
operator 10.0.0.5
$ awk '$5 ~ /^sudo/ {print $6, $NF}' sample-secure.log
student update
$ awk '/Failed/ && /root/ {n++} END {print n+0}' sample-secure.log
3
$ awk -F: '$3 >= 1000 && $3 < 60000 {print $1, $7}' /etc/passwd   # regular users

n+0 prints 0 instead of an empty string when nothing matched.

Variables, printf, and -v

awk variables need no declaration. Unset variables are 0 as numbers and empty as strings. -v passes a shell value into awk, which is safer than splicing $var into a single-quoted program:

$ awk -v ip=203.0.113.7 '$0 ~ ip {n++} END{print ip, n}' sample-secure.log
203.0.113.7 3
$ awk '/Failed/ {f++} /Accepted/ {a++} END {printf "failed=%d accepted=%d rate=%.1f%%\n", f, a, f*100/(f+a)}' sample-secure.log
failed=7 accepted=2 rate=77.8%

printf uses C formats: %s string, %d integer, %.1f decimal, %-15s left-aligned width 15, %5d right-aligned width 5, and %% for a literal percent sign. Unlike print, it adds no newline.

Associative arrays

awk arrays are indexed by strings, which makes counting and grouping easy:

$ awk '/Failed/ {c[$(NF-3)]++} END {for (k in c) printf "%-15s %d\n", k, c[k]}' sample-secure.log | sort -k2,2nr
192.168.1.50    3
203.0.113.7     3
192.168.1.10    1
$ awk '{split($3, t, ":"); h[t[1]":"t[2]]++} END{for(k in h) print k, h[k]}' sample-secure.log | sort
08:01 2
08:02 1
08:03 3
08:05 1
08:06 2
08:07 1
  • The first example counts back from the end of the line with $(NF-3), so invalid user doesn't affect it. That is a second fix for the field shift.
  • for (k in a) visits keys in no fixed order. Pipe to sort when order matters.
  • (k in a) tests whether a key exists without creating it, and delete a[k] removes an element.
  • A subscript like seen[ip, user] joins both values into one key with SUBSEP. !seen[key]++ is the classic dedupe idiom: it is true only the first time a key appears.

Built-in functions

Function Effect

substr(s, start, len) substring, 1-based
index(s, t) position of t in s
split(s, arr, sep) split into an array; returns the element count
sub(re, repl, target) replace the first match; defaults to $0
gsub(re, repl, target) replace every match
match(s, re) sets RSTART and RLENGTH
tolower(s) / toupper(s) change case
sprintf(fmt, ...) format and return a string
system(cmd) run a shell command 
$ awk '/sudo/ {sub(/.*COMMAND=/, ""); print}' sample-secure.log
/usr/bin/dnf update
$ awk '{gsub(/[0-9]+/, "N", $5); print $5}' sample-secure.log | sort | uniq -c
      9 sshd[N]:
      1 sudo[N]:
$ awk 'match($0, /port [0-9]+/) {print substr($0, RSTART+5, RLENGTH-5)}' sample-secure.log | head -3
50122

$ awk 'BEGIN{n=split("a,b,c", p, ","); print n, p[2]}'

User-defined functions

$ awk 'function ipclass(ip) { return (ip ~ /^(10|192\.168)\./) ? "private" : "public" }
       /from/ {print $(NF-3), ipclass($(NF-3))}' sample-secure.log | sort -u
10.0.0.5 private
192.168.1.10 private
192.168.1.50 private
203.0.113.7 public

Several files: NR==FNR

While awk reads the first file, NR equals FNR. That lets you load a lookup table into an array first and then process the second file, which amounts to a join between two files:

$ printf '192.168.1.50 lab-gateway\n203.0.113.7 external-scanner\n' > known-hosts.txt
$ awk 'NR==FNR {name[$1]=$2; next}
       /Failed/ {ip=$(NF-3); print ip, (ip in name ? name[ip] : "unknown")}' \
      known-hosts.txt sample-secure.log | sort | uniq -c
      1 192.168.1.10 unknown
      3 192.168.1.50 lab-gateway
      3 203.0.113.7 external-scanner

next moves straight to the next record and skips the remaining rules.

Changing the record separator

RS="" turns on paragraph mode, where blank lines separate records. With FS="\n", each line becomes a field:

$ printf 'name: a\nage: 1\n\nname: b\nage: 2\n' | awk 'BEGIN{RS=""; FS="\n"} {print NR": "$1" / "$2}'
1: name: a / age: 1
2: name: b / age: 2

getline

getline reads input on demand. It is mostly used in BEGIN blocks to read another file or a command's output:

awk 'BEGIN { while ((getline line < "known-hosts.txt") > 0) n++; print n }'   # prints 2
awk 'BEGIN { "date +%Y" | getline y; close("date +%Y"); print "year:", y }'

getline returns 1 on success, 0 at end of input, and -1 on error. Write the loop condition as > 0 so a missing file doesn't cause an infinite loop, and call close() when you are done with a command or file. In most cases NR==FNR is simpler.

In the script: count and format the report

report=$(awk -v limit="$threshold" '
    {
        ip = $11; user = $9
        fails[ip]++
        if (!seen[ip, user]++)
            users[ip] = users[ip] (users[ip] ? "," : "") user
    }
    END {
        for (ip in fails)
            printf "%-15s %5d  %-20s %s\n", ip, fails[ip], users[ip],
                   (fails[ip] >= limit ? "ALERT" : "ok")
    }' <<< "$failed" | sort -k2,2nr -k1,1)
  • -v limit= passes the shell's threshold into awk.
  • fails[ip]++ counts per IP. seen[ip, user] dedupes user names per IP, and users[ip] joins them with commas.
  • In awk, writing two strings side by side concatenates them. The ternary cond ? a : b picks the status.
  • sort -k2,2nr -k1,1 sorts by column 2 numerically in descending order, then by IP, so the output is stable.

The complete script

#!/bin/bash
# log-audit.sh - summarize SSH login activity from secure-style logs
set -euo pipefail

usage() {
    echo "Usage: $(basename "$0") LOGFILE..." >&2
    echo "Env:   THRESHOLD=N (default 3)  OUTPUT=FILE (write report to FILE)" >&2
    exit 1
}

[ $# -ge 1 ] || usage
threshold=${THRESHOLD:-3}
[[ $threshold =~ ^[0-9]+$ ]] || { echo "error: THRESHOLD must be a number" >&2; exit 1; }

for file in "$@"; do
    if [ ! -r "$file" ]; then
        echo "error: cannot read $file" >&2
        exit 1
    fi
done

if [ -n "${OUTPUT:-}" ]; then
    exec > "$OUTPUT"
fi

failed=$(grep -hE 'sshd\[[0-9]+\]: Failed password' "$@" \
    | sed -E 's/ for invalid user / for /' || true)
accepted=$(grep -hE 'sshd\[[0-9]+\]: Accepted ' "$@" || true)

if [ -z "$failed" ]; then
    failed_total=0
else
    failed_total=$(wc -l <<< "$failed")
fi

echo "== SSH audit: $# file(s), threshold=$threshold =="
echo "Failed attempts: $failed_total"
echo
echo "-- Failed logins by source IP --"
printf '%-15s %5s  %-20s %s\n' "IP" "FAILS" "USERS" "STATUS"

report=""
if [ "$failed_total" -gt 0 ]; then
    report=$(awk -v limit="$threshold" '
        {
            ip = $11; user = $9
            fails[ip]++
            if (!seen[ip, user]++)
                users[ip] = users[ip] (users[ip] ? "," : "") user
        }
        END {
            for (ip in fails)
                printf "%-15s %5d  %-20s %s\n", ip, fails[ip], users[ip],
                       (fails[ip] >= limit ? "ALERT" : "ok")
        }' <<< "$failed" | sort -k2,2nr -k1,1)
    echo "$report"
fi

echo
echo "-- Successful logins --"
if [ -n "$accepted" ]; then
    awk '{ print $9, $11, $7 }' <<< "$accepted" | sort | uniq -c |
    while read -r count user ip method; do
        printf '%-10s from %-15s via %-9s x%d\n' "$user" "$ip" "$method" "$count"
    done
else
    echo "(none)"
fi

alerts=$(grep -c 'ALERT$' <<< "$report" || true)
if [ "$alerts" -gt 0 ]; then
    echo "$alerts source(s) reached the threshold" >&2
    exit 2
fi
exit 0

Runs and exit codes

Case Command Exit code
A source reached the threshold ./log-audit.sh sample-secure.log 2
Higher threshold, no alert THRESHOLD=5 ./log-audit.sh sample-secure.log 0
No arguments ./log-audit.sh 1, usage on stderr
Unreadable file ./log-audit.sh nope.log 1, error: cannot read nope.log
Threshold is not a number THRESHOLD=x ./log-audit.sh sample-secure.log 1
Report to a file OUTPUT=report.txt ./log-audit.sh sample-secure.log 2; the alert notice still reaches the terminal

The alert notice goes to stderr, so with OUTPUT=report.txt the report lands in the file and the notice stays on the terminal. From cron, you could use:

./log-audit.sh /var/log/secure > /tmp/audit.txt 2>&1 || [ $? -ne 2 ] || mail -s "SSH alert" root < /tmp/audit.txt

Ideas for further practice

  • Add a -t N command-line option instead of the environment variable (with getopts).
  • Read rotated /var/log/secure-* files, or take input from journalctl -u sshd.
  • Load an IP allowlist with NR==FNR and skip alerts for listed addresses.
