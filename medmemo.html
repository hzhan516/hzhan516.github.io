Recruiter takeaway

Why this project matters.

MedMemo demonstrates end-to-end ownership of a difficult AI product surface: desktop delivery, privacy constraints, model routing, local inference, memory retrieval, compliance wording, and user-facing review flows.

  • Local-first health data boundary

    Core data is designed to stay on the user's device, with SQLCipher/SQLite, local vector retrieval, and on-device AI paths.

  • Layered memory architecture

    Conversations become reviewable facts and recallable memory instead of being pushed directly into an LLM context window.

  • Multi-model provider routing

    OpenAI-compatible providers, local models, and provider health checks are organized behind replaceable interfaces.

  • Desktop product engineering

    Wails connects a Go backend with a React/TypeScript interface and cross-platform release concerns.

Architecture proof

Clear boundaries under product pressure.

The codebase is organized around Clean Architecture, compile-time dependency injection, local storage, AI adapters, memory use cases, and privacy pipelines.

Application shell

Wails v2, Go, React 18, TypeScript, Zustand, and desktop packaging.

Backend core

Clean Architecture, Google Wire, domain entities, use cases, repositories, and adapters.

AI and retrieval

LLM providers, ONNX Runtime, Hugot, embeddings, sqlite-vec, memory extraction, and confidence handling.

Safety positioning

MedMemo is a health information management and consultation-assistance tool. It is not a medical device and does not provide diagnosis, treatment, prescriptions, or medical decisions.
